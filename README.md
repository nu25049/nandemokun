# 暇な君へ

何をするか迷ったとき、本人が登録した行動候補から1件を提案するWebアプリ。

## 開発
`npm install` → `npm run dev` → http://localhost:3000

検証：`npm test`、`npm run typecheck`、`npm run build`。

候補はlocalStorageに保存されます。天気による室内候補への絞り込みに対応しています。Supabase・施設検索は未接続です。

## 天気と場所の条件（2026-10-09）
- 「室内だけにする」は位置情報なしでも利用できます。使える時間の条件と組み合わせて候補を絞ります。
- 「現在地の天気に合わせる」を押すと位置情報の許可を求め、概略座標（小数点以下2桁）をOpen-Meteoへ送信します。位置情報・天気は保存しません。
- 雨・雪・雷雨・霧のときは室内候補に限定します。晴れ・くもりのときは場所を制限しません。モデルによる現在天気の推定で、外出の安全を判定する機能ではありません。
- 位置情報の拒否、通信失敗、不正・古い応答では場所条件を解除し、時間条件を保った通常提案に戻ります。通信には8秒、位置取得には10秒のタイムアウトを設定しています。
- 条件に合う候補が0件なら提案を止め、条件変更や追加を案内します。候補一覧は削除しません。場所条件と天気情報は再読み込みでリセットされます。
- 天気データは90分を超えると解除されます。提供元：[Open-Meteo](https://open-meteo.com/)（[API仕様](https://open-meteo.com/en/docs)）。

最新の短い仕様報告は `制作内容/現在の仕様報告書.md` を参照してください。

## 第二回の追加機能
- 使える時間（指定なし / 5・15・30・60分以内）に合う候補から1件を提案します。対象0件なら時間条件の解除を案内します。
- 「同じ候補の連続を避ける」を有効にすると、別の対象候補がある場合は直前と違う候補を提案します。対象1件なら同じ候補を提案できます。

初期状態は時間指定なし・連続回避なしです。この2設定は再読み込みで初期状態に戻り、登録した候補は保持されます。提出用の記録は `制作内容/第2回週次進捗報告.md`。

制作計画は `制作内容/制作計画レポート.txt`、GeminiとCodexの相互共有場所は `制作内容/共有メモ.md`。
