# 任意ログインの接続手順

2026年10月25日時点ではSupabaseプロジェクト未作成。ゲストの提案・ゲーム・端末内の傾向調整は接続なしで利用できます。以下は管理者が後で行う設定であり、アプリからプロジェクトやテーブルを自動作成しません。

## 接続するもの

1. Supabaseでプロジェクトを作成する。
2. SQL Editorで `supabase/preferences.sql` を実行する。設定テーブルはログインした本人の行だけを読み書きできるRLSを持ちます。未ログインの読み書きは許しません。
3. AuthenticationのURL設定に本番のSite URL `https://softwearcreationwhatdo.vercel.app` と、Redirect URL `https://softwearcreationwhatdo.vercel.app/auth/confirm` を登録する。ローカル検証には `http://localhost:3000/auth/confirm` を追加する。
4. メール認証を有効にし、実際の宛先へ届く送信設定と送信制限を確認する。メールのリンクで同じブラウザーからログインするPKCE方式です。メールテンプレートを独自に変更する場合は、トークンを公開ログなどに残さず、公式の確認リンクの手順を確認する。
5. `.env.example` を参考にローカルの `.env.local` とVercelに、`SUPABASE_URL` と `SUPABASE_PUBLISHABLE_KEY` を設定する。利用するのは公開用publishable key（または従来のanon key）です。secret key・service_roleは使いません。環境変数の内容をGit、報告書、チャットへ貼らないでください。
6. 再ビルド・配備し、ホームの「好み・ログイン」でメールを入力する。メールリンクは発行したブラウザーで開きます。

## 実際に確認すること

- ログイン前も提案・候補管理・全ゲームが使えること。
- 本人のメールリンクが届き、期限内のリンクからログインできること。期限切れ・別ブラウザーでは失敗を案内すること。
- 好みを「アカウントに保存」し、別端末で同じアカウントにログインすると復元できること。
- 別のアカウントの設定を読めず、書き換えられないこと。SQLのRLSは実環境でも検証すること。
- ログアウトするとゲストの端末内設定へ戻ること。失敗したクラウド保存を成功と表示しないこと。

## 保存範囲

ログインして保存するのは13分類の出現傾向と直近回避の設定だけです。自作候補は従来どおりブラウザー内保存で、候補そのものの端末間同期は未実装。Canvasトークン・課題・現在地・店舗情報はアカウントへ送りません。店舗・課題の提案履歴も永続保存しません。

認証用のセッションはHTTP専用Cookieに保存し、クライアント側にSupabaseの認証SDKを置かない構成です。サーバーで `getUser()` により本人を確認し、所有者IDはリクエスト本文から採用しません。認証・設定APIと確認用リダイレクトはprivate/no-storeで返します。認証の更新はCookieを書き込めるAPIルートで行い、Server Componentで認証済みデータを描画する構成ではありません。

実メール送信・実DB保存・実RLS隔離はまだ検証していません。ローカルでは未設定時のゲスト利用、APIの本人確認と拒否処理、ログイン後UIの模擬応答を検証しています。
