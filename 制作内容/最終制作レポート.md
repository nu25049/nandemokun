## 2. 解決すべき課題と対象利用者（要求の原点）

- 対象とする単一の利用者（N=1）：授業の合間や外出先で空き時間ができたときに、何をするか決められない自分自身を対象とした。例えば、次の授業まで5分あるのに、課題を進めるか休憩するか迷い、SNSを見ているうちに休み時間が終わる場面である。
- 切実な不便と従来の代替手段の限界：従来は自分で候補を考えて選び、外出時には地図や天気も別々に確認していた。候補を探して比較する作業が増え、短い空き時間ほど行動を始めにくかった。候補の一覧を増やすだけでは、何をするか決める負担が残る。
- 提供する中核的価値：使える時間や状況を指定してボタンを押すと、今できる行動が1件提示され、具体的な手順で始められることである。最終改善では友人と一緒にいる場面にも対応し、会話やその場の遊びを1件決められるようにした。

## 3. プロダクトの機能概要・使い方・システム構成

- 主要機能と使い方：スマートフォンやPCで開き、空き時間、人数、人目、室内指定などを選んで提案ボタンを押すと、条件に合う行動を1件表示する。「ひとり」では手順付きカタログ144件や自分の候補を使い、手順チェックとタイマーで始められる。一時停止と途中からの再開、候補の追加・編集・削除、検索、お気に入り、実行・見送りの記録にも対応した。13分類の好みと、明示的な利用評価による任意の傾向調整を利用できる。「みんな」では2〜8人、1〜30分の会話・ことば遊び・観察・創作・軽い動き40件から、持ち物、始め方、手順、終了条件まで提示する。

  短時間で遊ぶために30秒タップと、計算・なぞなぞ・数列・ことば・豆知識○×の5種類を用意した。30秒タップは正解で10点加算、誤タップで10点減点し、下限を0点とする。自己ベストは終了時の得点で更新する。通常の5ゲームは種類・時間・タイマー方式別の自己ベストと次の目標を表示する。2〜4人がスマートフォンを交代して答える○×対決も実装し、全員の回答後に答えと順位を表示する。読み物は雑学200件と、出典・会話の一言付きの話題カード48件を収録した。○×160問、なぞなぞ96問、数列1,200問、ことば1,672問を用意し、一巡するまで同じ問題が出ないようにした。

- 動作例（スクリーンショットや図表を用いた説明を推奨）：図1は公開版で、1分の「机の上で指だけの散歩をする」を提案した画面である。開始リンクから手順とタイマーへ進み、一時停止後もホームから再開できる。

  図2は複数人提案を開発中に撮影した画面であり、現在は本番でも利用できる。人数と時間を選ぶと、会話やその場の遊びの始め方と終了条件が表示される。例えば「全員の好きなものを1つそろえる」では、食べ物を提案する声かけの例を見て会話を始め、一つ決まるか1分たったら終える。

  図3は30秒タップを開発中に撮影した画面であり、誤タップ減点と自己ベスト保存は現在、本番でも利用できる。正解数と誤タップ数を別に表示し、減点後の最終得点を自己ベストと比較できる。

- 採用した技術スタックとアーキテクチャ構成：フロントエンドはNext.js 16.4.5、React 19.3.0、TypeScript 5.9.3を採用した。提案やゲームを部品化し、候補・条件・得点のデータ形式を型で確認するためである。サーバー処理もNext.jsにまとめ、店舗とCanvas LMSを取得するAPIを置いた。保存にはlocalStorageを使い、候補・好み・履歴・ゲーム記録を同じブラウザーで保持する。JSONバックアップで別ブラウザーへ手動で引き継げる。当初計画のSupabaseとログインは最終改善で削除し、端末内保存で利用する構成に整理した。

  外部連携はOpen-Meteoの天気、Private.coffeeのOverpassによる店舗検索、nu.instructure.comのCanvas ToDo APIである。天気はブラウザーから取得し、店舗とCanvasはNext.jsのAPIを経由する。店舗一覧は直近の本番確認で取得に失敗しており、選んだ種類の店を地図で探す補助リンクを用意した。本人のCanvasトークンによる取得は確認待ちである。外部接続に失敗しても、端末内の候補やゲームは使える。GitHubでコードを管理し、Vercelへの自動配備で変更を公開する構成にした。

## 4. 8週間の垂直スライス開発とフィードバックによる改善の軌跡

- 週次イテレーションの歩み：授業期間を制作記録の第1〜7回と最終改善に対応させて振り返った。第1回は候補の追加・編集・削除、端末内保存、1件提案を作り、10月11日にNext.js版の本番動作を確認した。第2回は時間、連続回避、室内、天気の条件を追加した。第3回は例文を具体化し、1〜3分の入口、専用ゲーム、2回タップ、計算の桁数、タイマー2方式を整え、店舗とCanvasの連携も進めた。

  第4回はカタログを144件に増やし、なぞなぞ・数列・ことばと13分類の傾向調整を充実させた。第5回はお気に入り、直近100件の履歴、実行・見送りの評価を追加した。第6回はカタログ検索、手順とタイマー、バックアップと復元をつなげた。第7回は途中からの再開、人目の条件、スマートフォン向けメニュー、30秒タップ、累計点とレベルを追加し、11月16日に雑学200件と○×160問の本番動作を確認した。最終改善では複数人の行動提案、誤タップ減点、自己ベストを追加し、ログインを削除した。

- 利用者検証とピボット：利用者から「知らないことを一つ学ぶ」のような例文では何から始めるか分からないという指摘を受け、題材・手順・終了条件を具体化した。読みかけの本を持っている前提も見直し、青空文庫で作品を開くなど、その場で始められる内容にした。スマートフォンでページが縦に長いという指摘から、設定や履歴をメニューで切り替え、提案や短時間の入口へ進みやすくした。操作確認では幅320px、候補0件・1件、保存破損や書き込み失敗、別タブ同期を検証した。本人や友人による継続利用と、行動を決めるまでの時間の測定は今後行う。

- 発表会でのフィードバックと最終改善：11月16日の発表会では、複数人向けの暇つぶし、誤タップへのペナルティ、自己ベストの記録、ログインの削除、アプリ外で行う複数人の過ごし方の提案、当初の目的とのずれについて指摘を受けた。私はゲームや雑学を増やす中で、「次に何をするか決める」という中核が見えにくくなっていたと考えた。そこでホームの1件提案を軸にし、友人と会話やその場の遊びを始められる40件を追加した。

  誤タップの減点と自己ベストにより、正確に操作し、自分の記録を超える目標を持てるようにした。ログインを削除し、好みの保存を端末内とバックアップへまとめた。これらの変更は125件の自動テスト・型検査・本番ビルドに加え、公開URLでのブラウザー操作で確認した。実際の利用者による改善後の再評価は今後行う。

## 5. AIエージェントとハーネス活用の工学的総括

- エージェントと検証基盤（ハーネス）の活用：GeminiとCodexを活用し、計画の確認、実装、内容調査、検証、報告の整理を進めた。制作内容/共有メモ.mdに実装・検証結果・未完了事項・公開状況を記録し、並行作業はファイルごとに担当を分けた。AGENTS.mdに中核機能の維持、外部APIを必須にしないこと、秘密情報の扱い、型検査、主要操作の確認を定めた。TypeScriptの型検査、Vitest 5.0.3によるロジック検証、Playwrightによる画面操作を組み合わせた。最終改善では125件の自動テスト、型検査、本番ビルドが成功し、候補0件・1件、保存破損・保存失敗、複数人の条件と提案、好みの保存、320pxの表示を確認した。

- 直面した技術的課題と解決プロセス：候補数の多い分類に偏る問題には、分類を重み付きで抽選してから分類内の候補を選ぶ方式で対応した。対象0件でも除外条件を勝手に広げず、条件変更へ案内する。古い保存形式や不正データ、容量不足には検証と通知を加え、バックアップの書き込み途中で失敗した場合は元の値へ戻す。別タブで低い記録へ復元した後に、メモリ内の高い値を書き戻す問題は、正常に読めた最新の保存内容を優先するよう修正した。

  形タップの二重加点は手番IDで防ぎ、自己ベストは誤タップの減点を反映した終了時に確定する。店舗APIの取得失敗には地図への補助リンクを用意した。TechTrain RailwayのStation07〜10では、CSSのコンフリクト解消、git logとgit diffでの変更調査、リベース、タグ付けを学んだ。制作でも差分と履歴を確認し、生成したコードをテストと画面の両方で確かめる姿勢につなげた。
